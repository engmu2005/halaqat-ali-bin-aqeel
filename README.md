# تحضير درس بلوغ المرام – حلقات علي بن عقيل

سجل تحضير طلاب حلقات علي بن عقيل – درس بلوغ المرام – جمعية الدعوة.

نظام Web متعدد المستخدمين: يسجل المشرفون الدخول ويديرون الحلقات والطلاب ويسجلون التحضير من أي جهاز، والبيانات محفوظة في PostgreSQL ومصدر واحد للحقيقة.

## المميزات

- **تحضير اليومي**: اختيار التاريخ (ميلادي + هجري)، وتسجيل حالة كل طالب بضغطة واحدة: حاضر / متأخر / غائب / مستأذن، مع ملاحظة اختيارية لكل طالب في الجلسة. (أيام الأحد فقط ابتداءً من الأحد 27/09/2026.)
- **تحضير الجميع كحاضر** ثم تعديل الاستثناءات فقط.
- **مشاركة ملخص اليوم عبر واتساب** أو نسخه (أعداد الحضور وأسماء الغائبين والمتأخرين).
- **إدارة الطلاب والحلقات**: إضافة فردية، إضافة قائمة أسماء دفعة واحدة، استيراد من Excel/CSV، أرشفة الطالب بدون حذف سجله.
- **حسابات وصلاحيات**: مدير النظام (كل الصلاحيات) ومشرف (مقيد بالحلقات المسندة له)، مع إدارة الحسابات من الواجهة.
- **التقارير**: نسبة حضور كل طالب، إحصائيات الجلسات، تنبيهات الغياب المتتالي مع زر تواصل واتساب، فرز الجدول بأي عمود — كلها محسوبة فعلياً من قاعدة البيانات.
- **تصدير Excel** (ملخص الطلاب + السجل اليومي + الجلسات + معلومات) أو CSV، و**طباعة** بتنسيق مناسب.
- **نسخة احتياطية** JSON شاملة (بلا كلمات مرور) واستعادة آمنة، و**ترحيل تلقائي** للبيانات القديمة من النسخة المحلية السابقة.
- **سجل عمليات (Audit Log)** لكل العمليات المهمة.
- **تطبيق قابل للتثبيت (PWA)** بنفس الهوية البصرية.

## البنية التقنية

```
Frontend   الواجهة الحالية (HTML/CSS/JS بدون أطر عمل) — نفس التصميم
Backend    Node.js + Express (يقدّم الواجهة + REST API)
Database   PostgreSQL — المصدر الأساسي للحقيقة
Hosting    Render (Web Service + PostgreSQL، Auto Deploy من GitHub)
```

## التشغيل محلياً

المتطلبات: Node.js 18+ و PostgreSQL.

```bash
npm install
cp .env.example .env      # ثم املأ DATABASE_URL و SESSION_SECRET
createdb halaqat          # أو أنشئ قاعدة البيانات بأي طريقة
npm run migrate           # تطبيق المخطط
npm run create-admin      # إنشاء أول حساب مدير نظام
npm start                 # http://localhost:8080
```

لاختبار شامل (يحتاج DATABASE_URL):

```bash
npm test
```

عند تعديل ملفات الواجهة ارفع رقم الإصدار في `sw.js` (`CACHE`) حتى تُحدَّث النسخة المخزنة لدى المستخدمين.

## النشر على Render

```
GitHub  →  Render Web Service  →  PostgreSQL
```

1. أنشئ حساباً على [Render](https://render.com) واربط مستودعك GitHub.
2. **New → Blueprint** واختر هذا المستودع — سيقرأ `render.yaml` وينشئ Web Service + قاعدة تلقائياً، مع **Auto Deploy** من الفرع الرئيسي (كل دفع إلى `main` يُنشر مباشرة).
   - أو يدوياً: **New → Web Service** ثم اضبط:
     - Build Command: `npm ci && npm run migrate`
     - Start Command: `npm start`
     - Environment: `NODE_ENV=production` + `DATABASE_URL` (من قاعدة Render) + `SESSION_SECRET` (قيمة عشوائية طويلة) + `SESSION_TTL_DAYS=30`
3. بعد أول نشر: أنشئ أول مدير من جهازك ضد قاعدة الإنتاج:

   ```bash
   DATABASE_URL='<connection string من Render>' \
   SESSION_SECRET='<نفس قيمة Render>' \
   ADMIN_USERNAME='admin' ADMIN_PASSWORD='كلمة-مرور-قوية' \
   npm run create-admin
   ```

4. عطّل GitHub Pages (الموقع القديم) بعد التأكد من نجاح النشر: **Settings → Pages → Unpublish** حتى لا يبقى هناك نسخة ثابتة قديمة ببيانات محلية مضلِّلة.
5. للنقل من الأجهزة القديمة: سجّل دخول المدير من الجهاز الذي فيه بيانات النسخة السابقة وستظهر رسالة ترحيل البيانات تلقائياً.

## الأدوار والصلاحيات

| العملية | مدير النظام | المشرف |
|---|---|---|
| التحضير والملاحظات | كل الحلقات | حلقاته المسندة فقط |
| الطلاب: إضافة/تعديل/أرشفة/حذف | ✔ | داخل حلقاته |
| الطلاب: استيراد Excel/CSV | ✔ | (يستخدم إضافة قائمة الأسماء) |
| الحلقات: إضافة | ✔ | (تُسنَد له تلقائياً) |
| الحلقات: تعديل الاسم | ✔ | لحلقاته |
| الحلقات: حذف | ✔ (يصبح طلابها بدون حلقة) | للحلقات الفارغة فقط |
| التقارير والإحصائيات والتصدير | كل الحلقات | حلقاته |
| إعدادات الدرس والحساب | ✔ | (قراءة فقط) |
| إدارة الحسابات | ✔ | — |
| النسخ الاحتياطي والاستعادة والمسح | ✔ | — |
| سجل العمليات والترحيل | ✔ | — |

## أين تُحفظ البيانات؟

- **كل بيانات الطلاب والحلقات والتحضير والإعدادات** في PostgreSQL (على Render) — لا تُحفظ في المتصفح.
- **كلمات المرور** تُخزَّن مشفّرة بـ bcrypt ولا تظهر في أي استجابة أو نسخة احتياطية.
- **جلسة الدخول** كوكي آمنة `httpOnly` — لا توكنات أو أسرار في JavaScript.
- في `localStorage` يبقى فقط: علامة ترحيل البيانات القديمة، وبيانات النسخة المحلية القديمة (حتى يتأكد مالكها من نقلها)، وتفضيلات محلية غير حساسة.

## الأمان

- الأسرار كلها في Environment Variables (لا Database credentials أو API secrets في كود الواجهة).
- رؤوس أمان Helmet + تحديد محاولات تسجيل الدخول + منع حذف آخر مدير نظام.
- الـ Service Worker لا يخزّن مسارات `/api` إطلاقاً.
- كل عملية مهمة (دخول، إضافة، تعديل، حذف، تحضير جماعي، نسخ احتياطي، استعادة، ترحيل) تُسجَّل في سجل العمليات.
