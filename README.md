# halaqat-ali-bin-aqeel
# سجل حلقة بلوغ المرام – حلقات علي بن عقيل

نظام ويب لسجل تحضير وتسميع طلاب حلقة درس **بلوغ المرام** ضمن **حلقات علي بن عقيل – جمعية الدعوة**، يعمل مباشرة من GitHub Pages بدون أي خادم، ومصمم للجوال أولاً.

**الرابط:** https://engmu2005.github.io/halaqat-ali-bin-aqeel/

---

## الفكرة

- **الحلقة كل يوم أحد فقط** — لا يوجد تحضير يومي لبقية الأيام.
- كشوف الأحد **تُنشأ تلقائياً** بدءاً من الأحد القادم بعد أول تشغيل (لا تُنشأ كشوف بأثر رجعي إلا يدوياً بصلاحية المدير).
- **كل مشرف له حساب مستقل** يرى من خلاله حلقاته وطلابه وكشوفه فقط.
- **المدير (Admin)** يرى الجميع: يدير حسابات المشرفين (إضافة/تعديل/إيقاف)، وينقل الطلاب بين المشرفين، ويطلع على إحصائيات جميع الحلقات.
- جميع البيانات مترابطة في قاعدة بيانات واحدة: المشرف → الحلقة → الطالب → الدرس (الأحد) → الحضور → التسميع → الملاحظات → الإحصائيات. أي تعديل ينعكس فوراً على كل الشاشات لأن الإحصائيات تُحسب من نفس المصدر عند الطلب.

## الحسابات

| الدور | الصلاحيات |
|---|---|
| **مدير النظام** | كل شيء: المشرفون، جميع الطلاب والكشوف، الإحصائيات العامة، درس بأثر رجعي، مسح البيانات |
| **مشرف** | حلقاته وطلابه فقط: إضافة/تعديل طلابه، تحضير يوم الأحد، التسميع، الملاحظات، إحصائيات مجموعته |

- الدخول الافتراضي للمدير أول مرة: **اسم المستخدم `admin` وكلمة المرور `1234`** — غيّرها فوراً من «الإعدادات → حسابي».
- المدير ينشئ حساب مشرف (اسم مستخدم + كلمة مرور + اسم الحلقة) من تبويب «المشرفون»، ويمكنه إيقاف الحساب أو تصفير كلمة مروره.
- الصلاحيات مطبقة في **طبقة البيانات نفسها** (كل قراءة/كتابة تمر عبر فحص نطاق المشرف)، وليست مجرد إخفاء أزرار — لا يستطيع المشرف الوصول لبيانات مشرف آخر ولو عُدّلت الواجهة.

## الاستخدام اليومي (يوم الأحد)

1. يفتح المشرف حسابه → تبويب **التحضير**.
2. كشف الأحد موجود مسبقاً (أُنشئ تلقائياً) وفيه جميع طلابه.
3. لكل طالب: **حاضر / متأخر / غائب / مستأذن** + ملاحظة + زر **تسميع** (المتن، الحديث، التقييم: أتقن/جيد/يحتاج مراجعة/لم يتقن).
4. الحفظ **تلقائي فوري** في قاعدة البيانات المحلية، ولا تُفقد البيانات عند تحديث الصفحة.
5. في بقية الأيام تظهر رسالة «لا يوجد درس تحضير اليوم» ويُقفل التسجيل (التعديل بأثر رجعي للمدير فقط).

## ملف الطالب

من الضغط على اسم الطالب (في أي شاشة): المعلومات (المشرف، المجموعة، تاريخ الإضافة، الحالة) + ملخص الحضور ونسبته + سجل كل أحد بالتاريخ + سجل التسميع كاملاً + الملاحظات + زر مراسلة واتساب.

## حالة الطالب

- **نشط** يظهر في الكشوف القادمة.
- **منقطع/مؤرشف** يختفي من الكشوف القادمة وتبقى كل بياناته وسجلاته محفوظة، ويمكن للمشرف (أو المدير) إعادة تفعيله.
- الطالب الجديد يظهر في **الكشوف القادمة فقط** ولا يعدّل كشوف الأحد السابقة.
- عند **نقل الطالب بين المشرفين** (المدير) ينتقل لكشوف المشرف الجديد ويبقى سجله التاريخي كما هو.

## المزايا الإضافية

- **الوضع الليلي** 🌙 بزر في الترويسة (وفي شاشة الدخول والإعدادات) — يتبع إعدادات الجهاز تلقائياً حتى تخترق بنفسك، والاختيار محفوظ.
- مشاركة ملخص اليوم عبر **واتساب** أو نسخه.
- تنبيهات **الغياب المتتالي** مع رسالة جاهزة.
- **التقارير**: فترات (شهر/شهر سابق/30 يوم/كل الفترة/مخصص)، جدول الطلاب (فرز بالنقر)، جدول أحد الحلقة، إحصائيات المشرفين للمدير.
- **تصدير Excel** (أوراق: ملخص الطلاب، السجل اليومي، الأحد، التسميع، معلومات) وCSV، و**طباعة** منسقة.
- **استيراد الطلاب** من Excel/CSV.
- **نسخ احتياطي/استعادة** بملف JSON.
- **PWA**: يعمل بدون إنترنت بعد أول فتح، ويُثبّت على الجوال.

## تخزين البيانات

البيانات تُحفظ **محلياً في متصفح كل جهاز** (localStorage) ولا تُرفع لأي خادم. لذلك:

- استخدم النظام من جهاز واحد رئيسي، أو اعتمد التصدير/النسخ الاحتياطي للنقل بين الأجهزة.
- **خذ نسخة احتياطية دورياً** من: الإعدادات → تنزيل نسخة احتياطية.

## النشر على GitHub Pages

الموقع منشور تلقائياً من فرع `main`:

1. Settings → Pages → Deploy from a branch → `main` → `/ (root)`.
2. عند تعديل الموقع يعمل التحديث تلقائياً بعد كل دمج.

## النشر على Render (بديل إضافي)

المشروع موقع ثابت ولا يحتاج أي بناء (Build):

1. ادخل render.com بحساب GitHub.
2. **New + → Static Site** → اختر المستودع `engmu2005/halaqat-ali-bin-aqeel` (أول مرة: اضغط Install/Authorize لمنح Render وصولاً للمستودع).
3. الإعدادات:
   - **Name**: أي اسم (يحدد الرابط `https://<name>.onrender.com`)
   - **Branch**: `main`
   - **Root Directory**: اتركه فارغاً
   - **Build Command**: **اتركه فارغاً تماماً**
   - **Publish Directory**: اكتب `.` (نقطة)
4. **Create Static Site** — أول نشر يستغرق دقيقة تقريباً، وأي دمج جديد في `main` يعاد نشره تلقائياً (Auto-Deploy).

تنبيهات مهمة عن الخطة المجانية في Render:
- الموقع **يتوقف مؤقتاً بعد 15 دقيقة بدون زوار**، وأول زائر بعدها ينتظر 30–60 ثانية حتى يعمل.
- GitHub Pages (الرابط أعلاه) لا يتوقف أبداً — يُنصح به كموقع رئيسي، وRender إضافي أو لربط الدومين.

### دومين خاص على Render

1. اشترِ الدومين من أي مزوّد.
2. في Render: الموقع → **Custom Domains** → Add Custom Domain → اكتب الدومين.
3. سيُظهر لك Render قيمة سجل **CNAME** (غالباً `<اسم-موقعك>.onrender.com`).
4. عند مزوّد الدومين أضف سجل CNAME: للنطاق `www` القيمة أعلاه (وللنطاق الأساسي استخدم ALIAS/ANAME إن كان متاحاً أو استخدم GitHub Pages كما في الأعلى).
5. شهادة HTTPS تُصدر تلقائياً بعد تحقق DNS (قد يستغرق من دقائق إلى ساعات).

### ربط دومين خاص (مستقبلاً)

1. Settings → Pages → Custom domain واكتب الدومين.
2. عند مزوّد الدومين:
   - سجلات **A** للنطاق الأساسي: `185.199.108.153` و`185.199.109.153` و`185.199.110.153` و`185.199.111.153`
   - سجل **CNAME** لـ `www` يشير إلى `engmu2005.github.io`
3. بعد التحقق فعّل **Enforce HTTPS**.

## للتوسعة مستقبلاً

البنية جاهزة لإضافة: أكثر من حلقة/درس، تقارير شهرية وفصلية، تصدير PDF، متابعة حفظ المتن، تقييمات، إشعارات — دون تغيير في نموذج البيانات الحالي.

## التشغيل محلياً

```bash
python3 -m http.server 8080
# ثم افتح http://localhost:8080
```
